# Security — Аюулгүй байдал ба нууцлал

**Холбоос:** [backend_schema.md](./backend_schema.md) · [architecture.md](./architecture.md) · [ADR-004](./adr/ADR-004-rls-read-only.md) · [ADR-005](./adr/ADR-005-server-write-path.md)

---

## 1. Аюулын загвар

Хамгаалах зүйлс: бүртгэлийн хандалт, ярианы түүх, үгсийн сан, тохиргоо, провайдерын түлхүүр, үйлчилгээний хэрэглээ (зардал), ахицын өгөгдлийн бүрэн бүтэн байдал.
Таамаглал: client-ийн хүсэлтийг өөрчилж болно; Supabase-ийн нийтийн (anon) түлхүүр browser-т ил тул нэвтэрсэн хэрэглэгч PostgREST-ийг шууд дуудаж чадна; хэрэглэгчийн текст хорлонтой заавар агуулж болно.

## 2. Нэвтрэлт ба эрх

- Supabase Auth: **имэйл OTP (6 оронтой код)**, нууц үггүй. Google нэвтрэлт 2-р шатанд.
- Pilot урилгаар: Supabase Auth-д нийтийн бүртгэлийг хааж, admin скриптээр урилгатай хэрэглэгчийг үүсгэнэ; OTP нь шинэ хэрэглэгч үүсгэхгүй горимоор (`shouldCreateUser: false`). Тохиргоог **шалгах шаардлагатай**.
- Нийтийн мессеж бүртгэл/урилга байгаа эсэхийг илчлэхгүй ("Хэрэв таны имэйл бүртгэлтэй бол код илгээгдлээ").
- OTP-ийн хүчинтэй хугацаа, дахин илгээх ба буруу оролдлогын хязгаар — Supabase-ийн тохиргоогоор, **шалгах шаардлагатай**.
- Production SMTP — **шалгах шаардлагатай**.
- Анхны нэвтрэлтэд 18+ баталгаажуулалт заавал (`profiles.age_confirmed_at`).
- Хэрэглэгчийг зөвхөн сервер талын баталгаажсан session-оос тодорхойлно.
- Хамгаалагдсан үйлдэл бүрт эзэмшлийг шалгана.
- Client-ийн `user_id`, role, эзэмшлийн тэмдэглэгээнд хэзээ ч итгэхгүй.
- Cookie: HttpOnly, Secure, SameSite=Lax.

## 3. Өгөгдлийн сан

- `public` schema-ийн **бүх** хүснэгтэд RLS асаалттай; CI-д шалгана.
- Хэрэглэгчийн session-тэй client-д зөвхөн `select` policy (өөрийн мөр). `insert`/`update`/`delete` policy байхгүй (ADR-004).
- Бичилт: нэг мөрийн бичилт — `src/lib/supabase/admin.ts` (service role, `server-only`), эзэмшлийг кодоор шалгана; олон алхамт транзакц — DB функц (ADR-005).
- DB функцууд: `revoke execute ... from public, anon, authenticated`; зөвхөн `service_role`. `security invoker`, `set search_path = ''`. Supabase-ийн default privilege-ийг **шалгах шаардлагатай**.
- Эцэг-хүүхдийн эзэмшлийн тууштай байдлыг **composite FK** (`(parent_id, user_id)`) баталгаажуулна.
- Агуулгын хүснэгт, `ai_usage_events`, `usage_counters`-т энгийн хэрэглэгч бичихгүй.
- Хамгийн бага эрхтэй түлхүүр; service role түлхүүр browser-т хэзээ ч орохгүй.
- Зөвхөн Supabase client эсвэл parametrized query.

## 4. Нууц түлхүүр

- LLM түлхүүр, service role зэрэг нь зөвхөн серверийн орчны хувьсагч (Vercel env).
- `NEXT_PUBLIC_` угтвартай хувьсагчид нууц хэзээ ч бүү хий.
- `.env.local`, токен, түлхүүр, production өгөгдлийг commit хийхгүй; `.env.example`-д зөвхөн нэр.
- CI-д secret scanning (M1-ээс).
- Staging ба production нь тусдаа Supabase төсөл, тусдаа түлхүүртэй.
- Ил гарсан түлхүүрийг **нэн даруй** эргүүлнэ.

## 5. AI-тай холбоотой эрсдэл

| Эрсдэл | Хариу |
|---|---|
| Prompt injection | Хэрэглэгчийн текстийг system заавраас тусгаарлаж (`<learner_message>`) тэмдэглэнэ; AI-д tool, DB хандалт өгөхгүй; injection eval |
| AI-аар үгийн төлөв хуурамчаар өсгөх | Сервер зөвхөн тухайн session-ий mission `key`-г хүлээн авна; тоолуур session тутамд ≤ +1 |
| AI эрхийн шийдвэр гаргах | AI хэзээ ч эрх, бүртгэлийн төлөв, хязгаарыг шийдэхгүй |
| Буруу бүтэцтэй гаралт | Zod шалгалт → хязгаартай retry → аюулгүй алдаа |
| Аюултай HTML | AI-ийн гаралтыг энгийн текстээр render; `dangerouslySetInnerHTML` хориотой |
| Зохисгүй агуулга | System prompt-д хил хязгаар; сценариас хазайвал эелдгээр буцаах. Pilot 18+ тул нэмэлт moderation хэрэгслийг хойшлуулсан (хүлээн зөвшөөрсөн эрсдэл) |
| Хэт их хувийн мэдээлэл | Провайдерт имэйл, нэр илгээхгүй; онбордингт "Хувийн мэдээллээ бүү бичээрэй" сануулга |

## 6. Вэб аппын хамгаалалт

- Бүх оролтыг сервер дээр шалгана (мессеж ≤ 1000 тэмдэгт).
- **CSRF:** мутаци хүлээн авах Route Handler бүр `Origin` header-ийг `NEXT_PUBLIC_SITE_URL`-тай тулгана (байхгүй эсвэл зөрвөл `403`); cookie SameSite=Lax. Server Actions MVP-д ашиглахгүй (M2).
- Production-д HTTPS (HSTS).
- Security header (M1): CSP (тестлэгдсэн), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (2-р шатанд `microphone=(self)`), `frame-ancestors 'none'`.
- Файл байршуулалт MVP-д байхгүй; нэмбэл хэмжээ, төрлийг хязгаарлана.

## 7. Хэтрүүлэн ашиглах ба зардал

- Хэрэглэгч бүрийн өдрийн хязгаар (Asia/Ulaanbaatar өдөр): AI хариу 40, hint 10; feedback session тутамд 1 + 1 regenerate.
- DB тоолуур (`usage_counters`), атомар нэмэлт; давхардсан хүсэлт квот хасахгүй.
- Нэг session-д `pending` мессеж байхад шинэ мессеж хүлээж авахгүй.
- Нийт өдрийн төсвийг M6-ийн хэмжилтийн дараа тогтооно; провайдерын зардлын alert (боломжтой бол).
- Timeout, нийт хугацааны төсөв, ≤ 2 оролдлого (`trd.md §5`).
- IP-ээр rate limit: урилгаар pilot-д **хүлээн зөвшөөрсөн эрсдэл** (бүх AI endpoint нэвтрэлт шаардана, бүртгэл хаалттай). Нийтэд нээхээс өмнө эргэн харна.

## 8. Нууцлал ба хадгалах хугацаа

- Pilot эхлэхээс өмнө монгол хэлээр нууцлалын бодлого нийтэлнэ (M13).
- Зөвхөн шаардлагатай өгөгдлийг цуглуулна.
- Хадгалах хугацаа:
  - Яриа, үгсийн сан — бүртгэл идэвхтэй байх хугацаанд.
  - `ai_usage_events` — 12 сар; бүртгэл устгахад нэргүй болно (`user_id → null`).
  - Backup — Supabase-ийн төлөвлөгөөний дагуу (**шалгах шаардлагатай**).
- Бүртгэл устгах: хүсэлтээс хойш 7 хоногийн дотор admin гараар устгана. Бүх хадгалалтыг шалгахаас өмнө "бүрэн устгагдсан" гэж хэлэхгүй.
- Хэрэглэгчийн агуулгыг тодорхой мэдэгдэл, зөвшөөрөлгүйгээр хоёрдогч зорилгод (сургалт г.м.) ашиглахгүй.
- **Pilot зөвхөн 18+.** Насанд хүрээгүйчүүд, эцэг эхийн зөвшөөрөл ба хуулийн review хойшлогдсон.
- Монгол Улсын Хувь хүний мэдээлэл хамгаалах тухай хуулийг баримтална (нийтэд нээхээс өмнө хуулийн review — хойшлогдсон).
- Өгөгдлийн байршил: Ази бүс (`trd.md §6`).
- Логт мессежийн агуулга, имэйл, токен бичихгүй — зөвхөн ID.
- **2-р шат (дуу):** аудиог default-аар хадгалахгүй; зөвхөн транскрипт.

## 9. Баталгаажуулалт

- Хэрэглэгч хоорондын унших/өөрчлөх/устгах оролдлогыг API-гаар болон anon түлхүүртэй Supabase client-ээр шууд тестлэнэ.
- `authenticated` хэрэглэгч хүснэгтэд шууд бичих, DB функц дуудах оролдлого унахыг тестлэнэ.
- Browser bundle, network хариунд нууц байгаа эсэхийг шалгана.
- Хамаарлыг scan хийж, шинэчлэлтийг хянана.
- RLS policy, grant, migration-ийг review хийнэ.
- Энэ баримт байгаа нь апп "аюулгүй" гэсэн үг биш — хэрэгжүүлэлтийг шалгана.

## 10. Хариу арга (incident)

1. Илрүүлэх (алдааны хяналт, alert)
2. Нөлөөлсөн түлхүүрийг эргүүлэх
3. Хамрах хүрээг тогтоох
4. Хуулийн шаардлагын дагуу хэрэглэгчдэд мэдэгдэх
5. Дараах дүгнэлт
